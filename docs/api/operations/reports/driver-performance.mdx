# Get Driver Performance Report

<Endpoint
  method="GET"
  path="/api/v1/web-app/reports/driver-performance"
  auth="Bearer token"
  permission="read-driver_performance_report"
/>

Returns a paginated, **per-order** breakdown of how long each stage of delivery took — from the
order entering Pending through to it being delivered — for a chosen date range.

Use it to find where time is lost across a fleet: orders waiting to be assigned, drivers slow to
accept, long dwell at pickup, or repeated holds. Pass `export=true` to stream the full result set as
a CSV instead of paginated JSON.

:::caution Repeat the parameter; do not comma-separate
`supplierIds`, `driverIds` and `orderStatusIds` are array parameters. Send
`?supplierIds=12&supplierIds=45`. A comma-separated `?supplierIds=12,45` is rejected as a validation
error, because `12,45` is not an integer.
:::

## Request example

<Tabs groupId="lang">
<TabItem value="curl" label="cURL">

```bash
curl --request GET \
  --url 'https://sandboxapi.allowmena.com/api/v1/web-app/reports/driver-performance?startDate=2026-09-01&endDate=2026-09-10&supplierIds=12&supplierIds=45&limit=50' \
  --header 'Authorization: Bearer YOUR_TOKEN'
```

</TabItem>
<TabItem value="python" label="Python">

```python
import os
import requests

# A list value makes requests repeat the parameter: supplierIds=12&supplierIds=45
params = {
    "startDate": "2026-09-01",
    "endDate": "2026-09-10",
    "supplierIds": [12, 45],
    "limit": 50,
}

response = requests.get(
    "https://sandboxapi.allowmena.com/api/v1/web-app/reports/driver-performance",
    headers={"Authorization": f"Bearer {os.environ['ALLOW_TOKEN']}"},
    params=params,
    timeout=60,
)
response.raise_for_status()

body = response.json()
print(f"{body['count']} orders in range")
for row in body["data"]:
    print(row["orderId"], row["driverName"], row["totalDeliveryTimeMinutes"])
```

</TabItem>
<TabItem value="js" label="JavaScript">

```javascript
const url = new URL(
  'https://sandboxapi.allowmena.com/api/v1/web-app/reports/driver-performance',
);
url.searchParams.set('startDate', '2026-09-01');
url.searchParams.set('endDate', '2026-09-10');
url.searchParams.set('limit', '50');
// append, not set — each id is its own occurrence of the parameter
for (const id of [12, 45]) url.searchParams.append('supplierIds', String(id));

const response = await fetch(url, {
  headers: { Authorization: `Bearer ${process.env.ALLOW_TOKEN}` },
});

const body = await response.json();
console.log(`${body.count} orders in range`);
for (const row of body.data) {
  console.log(row.orderId, row.driverName, row.totalDeliveryTimeMinutes);
}
```

### Exporting to CSV

```bash
curl --request GET \
  --url 'https://sandboxapi.allowmena.com/api/v1/web-app/reports/driver-performance?startDate=2026-09-01&endDate=2026-09-10&export=true' \
  --header 'Authorization: Bearer YOUR_TOKEN' \
  --output driver-performance.csv
```

The response is a CSV file stream, not the JSON envelope. Pagination parameters are ignored — the
whole matching set is written.

:::note A null duration means the stage did not occur
Stage fields are null rather than zero when the transition never happened — a cancelled order has no
`pickedUpToDeliveredMinutes`. Do not treat null as `0` when averaging; exclude those rows.
:::

### The driver on each row is whoever delivered it

Rows attribute the order to the driver who **actually delivered** it, not whoever it was first
assigned to. Two consequences:

- An order that was reassigned is credited to the final driver.
- An order that was never delivered has `driverId: null` and **will not match a `driverIds`
  filter** — filtering by driver silently excludes undelivered orders.
