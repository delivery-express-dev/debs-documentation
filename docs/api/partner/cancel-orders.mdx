# Cancel Orders

<Endpoint method="DELETE" path="/api/v2/external/orders" auth="x-api-key header" />

Cancels one or more orders. Unlike create, this endpoint is **not** all-or-nothing: each order is
attempted independently and you get a result row for every one, so a batch containing an
already-delivered order still cancels the rest.

Use it when a customer cancels, or when you need to withdraw an order you dispatched by mistake.
Cancellation is only possible before the order reaches a terminal state — an order already
`Cancelled` or `Delivered` is rejected with a per-order `409`.

:::note The order id goes in the body, not the path
This is a `DELETE` with a request body addressing a collection. There is no
`DELETE /orders/{order_id}` form. Some HTTP clients strip bodies from `DELETE` requests by
default — verify yours sends it.
:::

## Request example

<Tabs groupId="lang">
<TabItem value="curl" label="cURL">

```bash
curl --request DELETE \
  --url 'https://sandboxapi.allowmena.com/api/v2/external/orders' \
  --header 'x-api-key: YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "orders": [
      { "order_id": 27040, "reason": "Customer changed their mind" },
      { "order_id": 26285, "reason": "Out of stock" }
    ]
  }'
```

</TabItem>
<TabItem value="python" label="Python">

```python
import os
import requests

response = requests.delete(
    "https://sandboxapi.allowmena.com/api/v2/external/orders",
    headers={"x-api-key": os.environ["ALLOW_API_KEY"], "Content-Type": "application/json"},
    json={
        "orders": [
            {"order_id": 27040, "reason": "Customer changed their mind"},
            {"order_id": 26285, "reason": "Out of stock"},
        ]
    },
    timeout=30,
)

body = response.json()

# 200 means every order cancelled; 207 means inspect each row.
for result in body["data"]:
    if result["status_code"] != 200:
        print(f"order {result['order_id']} not cancelled: {result['message']}")
```

## Response

The HTTP status tells you whether the batch was clean:

- **`200 OK`** — every order in the batch was cancelled.
- **`207 Multi-Status`** — at least one order failed. The batch was still processed; read each row.

Both carry the same body shape.

```json title="200 — all cancelled"
{
  "status": true,
  "message": "Success",
  "data": [
    { "order_id": 27040, "status_code": 200, "message": "Order canceled successfully" },
    { "order_id": 26285, "status_code": 200, "message": "Order canceled successfully" }
  ]
}
```

```json title="207 — partial success"
{
  "status": true,
  "message": "Success",
  "data": [
    { "order_id": 27040, "status_code": 200, "message": "Order canceled successfully" },
    { "order_id": 231231, "status_code": 404, "message": "Order not found" },
    { "order_id": 26285, "status_code": 409, "message": "Order already cancelled" }
  ]
}
```

:::caution `status` is `true` even on a 207
The top-level `status` reports that the batch was processed, not that every order succeeded. Always
check the HTTP status, or each row's `status_code` — never just `status`.
:::

### Per-order outcomes

<ErrorTable
  errors={[
    { status: 200, when: <><code>Order canceled successfully</code>.</> },
    { status: 404, when: <><code>Order not found</code> — no such order id.</> },
    { status: 409, when: <><code>Order already cancelled</code> — the order is already in the Cancelled state.</> },
    { status: 409, when: <><code>Order already delivered</code> — delivered orders cannot be cancelled through this endpoint.</> },

  ]}

## Request-level errors

These reject the whole request; no order is cancelled and there is no `data` array.

## Side effects

Cancelling an order does more than change its status:

- The cancellation reason is written to the order history.
- If a driver was assigned, they are unassigned and their workload counters are adjusted; remaining
  orders on that driver's route have their ETAs recalculated.
- **Refunds depend on how far the order got.** An order not yet picked up (or on hold) is refunded to
  the branch wallet; once picked up, the delivery charge stands.
- An [order-status webhook](/api/webhooks/order-status) fires, carrying your `supplier_reference_id`
  and the cancellation reason in `notes`.

## Differences from the published Postman collection

:::warning
The collection's **Cancel Order** example shows a `400` response body of
`{"message": "Not a valid string.", "status": false}`. The current backend returns
`{"status": false, "message": "Invalid request"}` for the same class of failure — the raw
serializer text is no longer surfaced. The collection also omits the `x-api-key` header from this
request, but the header is required.
:::
