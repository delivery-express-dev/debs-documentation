# Create Order (v1)

<Endpoint method="POST" path="/api/v1/external/orders" auth="x-api-key header" />

The original create-order endpoint. It creates **on-demand orders only** and accepts a much smaller
field set than v2 and v3.

:::warning Legacy
v1 is documented for integrations already running on it. New integrations should use
[v3](/api/partner/create-order-v3). v1 cannot schedule deliveries, cannot carry pickup contact
details, cart items, collection method or pickup instructions, and has no `avenue` field on the
drop-off.
:::

## What v1 does not support

| Capability | Available in |
| --- | --- |
| `schedule` — delivery windows | v2, v3 |
| `pickup.name`, `pickup.mobile` and pickup address fields | v2, v3 |
| `pickup.item_details` — cart line items | v2, v3 |
| `pickup.collection_method` | v2, v3 |
| Pickup instructions | v2 (notes), v3 (notes + attachments) |
| `drop-off.avenue` | v2, v3 |

Every order created through v1 is **On-Demand**.

## Request example

<Tabs groupId="lang">
<TabItem value="curl" label="cURL">

```bash

  --url 'https://sandboxapi.allowmena.com/api/v1/external/orders' \
  --header 'x-api-key: YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "orders": [
      {
        "pickup": { "latitude": 29.320556, "longitude": 48.037866 },
        "drop-off": {
          "latitude": 29.376,
          "longitude": 47.977,
          "area": "Jabriya",
          "name": "Sara Al-Ali",
          "mobile": "77669900",
          "block": "Block 1",
          "street": "4",
          "building": "5",
          "notes": "Leave with reception"
        },
        "supplier_reference_id": "SP-1001",
        "payment_type": 1,
        "total_amount": 45.000
      }
    ]
  }'
```

```python
import os
import requests

response = requests.post(
    "https://sandboxapi.allowmena.com/api/v1/external/orders",
    headers={"x-api-key": os.environ["ALLOW_API_KEY"], "Content-Type": "application/json"},
    json={
        "orders": [
            {
                "pickup": {"latitude": 29.320556, "longitude": 48.037866},
                "drop-off": {
                    "latitude": 29.376,
                    "longitude": 47.977,
                    "name": "Sara Al-Ali",
                    "mobile": "77669900",
                },
                "supplier_reference_id": "SP-1001",
                "payment_type": 1,
                "total_amount": "45.000",
            }
        ]
    },
    timeout=30,
)

body = response.json()
if not body["status"]:
    raise RuntimeError(f"Order rejected ({response.status_code}): {body['message']}")

print(body["data"])
```

`200 OK`

```json

  "status": true,
  "message": "Success",
  "data": [
    { "order_id": 19444, "supplier_reference_id": "SP-1001" }
  ]
}
```

## Note on payment status

v1 records every order's payment status as **Pending**, regardless of `payment_type`. v2 and v3
instead mark `payment_type: 2` (Online) orders as **Completed** with nothing due on delivery. If
your reconciliation reads payment status, this difference matters — another reason to move to v3.
