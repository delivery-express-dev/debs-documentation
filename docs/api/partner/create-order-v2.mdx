# Create Order (v2)

<Endpoint method="POST" path="/api/v2/external/orders" auth="x-api-key header" />

Submits one or more delivery orders for the supplier branch behind your API key. v2 is the previous
generation of the create endpoint: it is still fully supported, and is what most existing
integrations run on.

**Use [v3](/api/partner/create-order-v3) for new work.** v2 is identical except for how pickup
instructions are expressed, and v2 cannot carry attachments.

## Differences from v3

| | v2 | v3 |
| --- | --- | --- |
| Pickup instruction notes | `pickup.notes` — a plain string | `pickup.instructions.notes` |
| Pickup instruction attachments | Not supported | `pickup.instructions.attachments[]` |
| Everything else | Identical | Identical |

A `pickup.notes` value sent to v3 is ignored, and a `pickup.instructions` object sent to v2 is
ignored. The two are not interchangeable.

## Request body

The order object, drop-off object, pickup object and schedule object are **exactly as documented for
[v3](/api/partner/create-order-v3#request-body)**, with the single substitution above. Rather than
repeat forty fields, this page documents only what differs.

  title="Pickup — v2-only field"

    { name: 'notes', type: 'string', required: false, description: 'Free-text pickup instructions for the driver, recorded as a pickup-instruction note on the order. In v3 this moved to pickup.instructions.notes.' },

## Response

`200 OK` — identical to v3.

```json
{
  "status": true,
  "message": "Success",
  "data": [
    { "order_id": 19444, "supplier_reference_id": "SHOP-1001" }
  ]
}
```

## Batch behaviour

The batch is created in one transaction: if any order fails, none are created. See
[v3 — Batch behaviour](/api/partner/create-order-v3#batch-behaviour).

## Errors

Identical to [v3](/api/partner/create-order-v3#errors), minus the three attachment-specific messages,
which v2 cannot produce.
