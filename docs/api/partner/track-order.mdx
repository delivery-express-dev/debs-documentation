# Track Order

<Endpoint method="GET" path="/api/v2/external/orders/{order_id}/tracking" auth="x-api-key header" />

Returns an order's current status and, while it is in flight, the assigned driver's contact details,
last known position and estimated time to delivery.

Use it to render a live tracking view for your customer, or to reconcile an order whose webhook you
missed. For ongoing updates prefer [webhooks](/api/webhooks/overview) — they push each change
instead of making you poll.

## Path parameters

<ParamTable
  params={[
    { name: 'order_id', type: 'integer', required: true, description: <>Platform order id, as returned by <a href="/api/partner/create-order-v3">Create Order</a>. Must belong to the branch behind your API key.</>, example: '59332' },
  ]}
/>

This endpoint takes no query parameters and no request body.

## Request example

<Tabs groupId="lang">
<TabItem value="curl" label="cURL">

```bash
curl --request GET \
  --url 'https://sandboxapi.allowmena.com/api/v2/external/orders/59332/tracking' \
  --header 'x-api-key: YOUR_API_KEY'
```

</TabItem>
<TabItem value="python" label="Python">

```python
import os
import requests

response = requests.get(
    "https://sandboxapi.allowmena.com/api/v2/external/orders/59332/tracking",
    headers={"x-api-key": os.environ["ALLOW_API_KEY"]},
    timeout=30,
)

body = response.json()
if not body["status"]:
    raise RuntimeError(f"Tracking failed ({response.status_code}): {body['message']}")

tracking = body["data"]
print("status:", tracking["order_status"]["slug"])

driver = tracking["driver"]
if driver:
    eta_seconds = driver["estimated_time_of_delivery"]
    print(f"{driver['name']} — about {eta_seconds // 60} minutes away")
```

</TabItem>
<TabItem value="js" label="JavaScript">

const response = await fetch(

## Response

`200 OK`

```json title="Driver assigned and en route"
{
  "status": true,
  "message": "Success",
  "data": {
    "driver": {
      "name": "John Smith",
      "country_code": "+965",
      "mobile": "98000001",
      "location": { "latitude": 29.3051261, "longitude": 47.800077 },
      "estimated_time_of_delivery": 520
    },
    "order_status": { "name": "Assigned", "slug": "assigned" }
  }
}
```

```json title="No driver to report"
{
  "status": true,
  "message": "Success",
  "data": {
    "driver": {},
    "order_status": { "name": "Delivered", "slug": "delivered" }
  }
}
```

:::caution `estimated_time_of_delivery` is in seconds
The value is a count of **seconds**, not minutes. The webhook payloads, by contrast, report their
ETAs in minutes — see [Driver Assigned](/api/webhooks/driver-assigned). Divide by 60 before showing
minutes to a customer.
:::

### When `driver` is empty

`driver` is `{}` — not `null`, not omitted — in either of these cases:

1. **The order is in a terminal or paused state**: `Cancelled`, `Delivered` or `Hold`. Driver
   details are deliberately withheld once the delivery is over.
2. **No driver is assigned yet**: the order is still `Created`, `Pending`, `Scheduled` or `Stacked`.

So an empty `driver` object is normal, not an error. Check `order_status.slug` to tell which case
you are in.

## Differences from the published Postman collection

:::warning
Two differences worth knowing:

- The collection's "404 - Order not found" example is **saved with status code 400**. The backend
  returns a genuine **404** for this endpoint. (The v1
  [Get Order Status](/api/partner/order-status) endpoint *does* return 400 for a missing order —
  that is likely where the collection's 400 came from.)
- The collection omits the `x-api-key` header from this request. It is required.
:::
